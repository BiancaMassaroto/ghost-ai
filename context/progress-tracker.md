## Architecture Decisions

- Route protection lives in `proxy.ts` at the project root, not `middleware.ts` — Next.js 16 renamed the file convention (`middleware` → `proxy`); the API and semantics are otherwise unchanged.
- Clerk `appearance` is themed once, centrally, in `lib/clerk-appearance.ts` (`{ theme: dark, variables: {...} }` using this Clerk version's `theme` key, not the older `baseTheme` prop) and passed to `ClerkProvider` in the root layout, rather than repeated per-component — all Clerk UI (`SignIn`, `SignUp`, `UserButton`) inherits it automatically.
- Project data flows server → client one-way: `app/editor/page.tsx` and `app/editor/[projectId]/page.tsx` fetch via `lib/get-projects.ts` and pass props down; `hooks/use-project-actions.ts` never holds its own copy of the project list, it triggers `router.refresh()`/`router.push()` after a mutation and lets the server component re-fetch. This replaces the earlier two-hook mock-data split (`useMockProjects` + `useProjectDialogs`) noted in prior sessions — superseded by `07-wire-editor-home.md`.
- A project's database `id` (Prisma `cuid()`) is the single identifier used everywhere, including as the future Liveblocks room ID — there is no separate stored "room ID" field. The create dialog's room-ID preview is cosmetic (client-generated slug+suffix) and does not become the real ID; see `07-wire-editor-home.md` notes above for why.
- `proxy.ts`'s middleware-level `auth.protect()` now applies only to page routes, not `/api`/`/trpc`. API routes enforce auth per-route instead (`lib/api-auth.ts`'s `requireUserId()`), because Clerk's `auth.protect()` doesn't return `401` for unauthenticated non-document (API) requests — it redirects or 404s. Any new `app/api/*` route must call `requireUserId()` itself; it will not get auth protection from `proxy.ts`.
- The page-background color token is exposed to Tailwind as `bg-canvas`, not `bg-base` (its CSS variable is still `--bg-base`). Registering it as `--color-base` collided with Tailwind's own font-size scale key `base` (`text-base` = 1rem); a color theme value wins that collision, so every `text-base` in the app (the create/rename project dialog inputs, `DialogTitle`, `Card` title, `Textarea`, the auth layout headline) was silently rendered as `color: var(--bg-base)` — near-black text on a near-black card — instead of getting a font size. See the reserved-name note in `context/ui-context.md`.
